# S24 2:4 Structured-Sparse VDOT — Final Implementation

## 1. Summary

This version extends XiangShan Kunminghu V2 with a 2:4 structured-sparse
signed-INT8 vector dot-product operation while retaining the original dense
8-lane `vdot.vv` operation. The sparse operation uses packed nonzero weights
and per-group 2:4 masks. It shares the eight signed-INT8 multipliers with
Dense VDOT inside `VIAluFix`.

The previous dense-only Hybrid CSA work is preserved in
[`DESIGN.md`](DESIGN.md) and [`RESULTS.md`](RESULTS.md); do not use the old
dense microbenchmark numbers as S24 application throughput.

## 2. Sparse operand and result contract

From the current S24 RTL source:

- `vs1[63:0]`: eight packed activation bytes;
- `vs2[63:0]`: eight nonzero signed-INT8 weights;
- `vs2[79:64]`: four 4-bit masks (each with exactly two bits set);
- `vd[31:0]` and `vd[63:32]`: two 32-bit sign-extended partial sums;
- `vd[127:64]`: zero.

The sparse operation checks `SEW=e8`, `LMUL=m1`, `VL=8`, `vstart=0`,
and valid 2:4 masks. The ALU uses mask-select logic ahead of the shared
multipliers, CSA compression, and registered outputs.

The dense encoding and sparse instruction encoding can be inspected in
[`patches/s24/`](../patches/s24/): `rocket-chip.patch`, `yunsuan.patch`,
`xiangshan.patch` and `nemu.patch`. The actual patch sources, not this
prose description, are authoritative for exact instruction encoding.

## 4. Functional testing

The final PairAcc INT8 workload was verified on XiangShan + NEMU Difftest.
The logs record:

- 32/32 predictions matching the Python INT8 reference;
- 31/32 correct classifications;
- matching intermediate dot-product and hidden-layer values;
- simulator exit through `HIT GOOD TRAP`.

The original dense functionality and S24 directed/ISA boundary tests are
separate from the 32-image application benchmark.

## 5. Full INT8 MLP performance

Network shape: **64 → 32 → 10**, 32 samples, 2:4 sparse weights,
3 warm-up rounds and 5 measured rounds.

| Same-run A/B implementation | Median cycles / 32 samples |
|---|---:|
| Specialized | 19,387 |
| **PairAcc (selected)** | **19,308** |

This comparison measures a small, complete, INT8 MLP application on the
simulated processor, not a single VDOT instruction or end-to-end LLM
inference. Historical RVV run values are **not** used to assert a same-run
apples-to-apples speedup.

Sources: [`software/VDOT_Real_INT8_PAIRACC/`](../software/VDOT_Real_INT8_PAIRACC/)
and [`PairAcc log summary`](../results/vdot-s24/real-int8-pairacc/summary.txt).

## 6. Synthesis and timing evidence

The current S24 mapped VIAluFix area is **49,354.172 um²** (Nangate45),
compared to **48,587.028 um²** with sparse disabled: **+1.579%** module
area overhead. FastSel reduces mapped module area by **0.330%** relative
to Pre-FastSel. Full area provenance, generic synthesis results, STA logs,
and limitations are documented in [`S24_PPA.md`](S24_PPA.md).

These are standard-cell mapped estimates, not placed-and-routed chip area.
No verified physical power or routed Fmax is reported.

## 7. Reproduction

Check out the exact upstream revisions recorded in `patches/s24/*-base.txt`
(including `xs-env-base.txt`) and initialize all submodules. From the folder
containing `xs-env` and `cie2026-jade-vdot`:

~~~bash
bash cie2026-jade-vdot/scripts/apply-s24-patches.sh "$(pwd)/xs-env"
~~~

Enter the xs-env Nix environment and build XiangShan/NEMU if they are not
already built. Run the self-contained final application benchmark:

~~~bash
cd xs-env
nix develop -c bash ../cie2026-jade-vdot/software/VDOT_Real_INT8_PAIRACC/run.sh
~~~

`run.sh` copies its versioned workload sources into the nexus-am app folder,
compiles that app and executes the simulator with Difftest. Its default
workspace root is `$HOME/work/xiangshan-vdot`, overrideable by
`VDOT_WORKSPACE`. The original `versions.env` and `scripts/apply-patches.sh`
remain for the **older dense/Hybrid** experiment, not S24.
