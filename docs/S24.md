# 2:4 结构化稀疏 VDOT 指令设计与实现

## 1. 设计概述

在 XiangShan 昆明湖 V2 的 `VIAluFix` 中增加 2:4 结构化稀疏 INT8 点积指令，并保留 Dense `vdot.vv`。两种运算共享 8 个 INT8 乘法器和 CSA 归约网络，保持原有单周期流水功能单元接口。

## 2. 指令语义

| 字段 | 2:4 稀疏指令 |
|---|---|
| `vs1[63:0]` | 8 个 INT8 激活值 |
| `vs2[63:0]` | 8 个打包的非零 INT8 权重 |
| `vs2[79:64]` | 4 组 4-bit 掩码，每组恰有两位为 1 |
| `vd[31:0]` | 第一个 32 位有符号部分和 |
| `vd[63:32]` | 第二个 32 位有符号部分和 |
| `vd[127:64]` | 清零 |

约束：`SEW=e8`、`LMUL=m1`、`VL=8`、`vstart=0`，不支持掩码执行。稀疏元数据不合法或配置不满足要求时产生非法指令异常。Dense `vdot.vv` 仍输出 8 对 INT8 元素的 32 位点积。编码和异常逻辑以 [`patches/s24/`](../patches/s24/) 中的 RTL 为准。

## 3. 数据通路

稀疏模式对每组 4 个激活值按 2:4 掩码选择 2 个，与对应的打包非零权重相乘。FastSel 直接使用掩码位生成选择信号，避免先编码索引再进行动态选择。8 个乘积通过两组 19 位 CSA 计算部分和，分别符号扩展为 32 位写回。

Dense 与稀疏模式由操作类型选择结果，输出通过 `VIAluFix` 的流水线寄存器对齐。NEMU 使用顺序 C 实现进行差分校验。

## 5. 验证与应用测试

Dense 指令回归、稀疏运算和 INT8 MLP 均通过相应 RTL–NEMU 测试。完整应用为 **64→32→10** 的两层稀疏 INT8 MLP，共 32 个样本：

| 指标 | 结果 |
|---|---:|
| 与 Python INT8 参考模型一致 | 32/32 |
| 分类正确 | 31/32 |
| Specialized | 19,387 cycles |
| **PairAcc** | **19,308 cycles** |

计时采用 3 次预热与 5 轮测量。PairAcc 仅改变第 0 层部分和的累加顺序，不修改指令或 RTL。应用源码及日志见 [`software/VDOT_Real_INT8_PAIRACC/`](../software/VDOT_Real_INT8_PAIRACC/) 与 [`results/vdot-s24/real-int8-pairacc/`](../results/vdot-s24/real-int8-pairacc/)。

## 6. 硬件评估

Nangate45 映射下，FastSel `VIAluFix` 面积为 **49,354.172 μm²**，相比禁用稀疏功能增加 **1.579%**。10 ns 理想时钟约束下，最差 Setup Slack 为 **2.71 ns**。测量方法及完整对比见 [`S24_PPA.md`](S24_PPA.md)。
