# 2:4 结构化稀疏 VDOT 指令与硬件实现

## 1. 设计目标

本参赛工程在 XiangShan 昆明湖 V2 的向量整数 ALU `VIAluFix` 中，同时支持常规有符号 INT8 点积 `vdot.vv` 和 2:4 结构化稀疏点积 `VDOT_S24_VV`。两种指令共享八个有符号 INT8 乘法器。稀疏指令增加掩码选择逻辑和独立结果写回选择，保留 Dense 指令的功能行为。

这是一套完整的指令扩展实现。Balanced Tree、CSA、Hybrid CSA、Fused Booth + CSA 等是设计探索时比较过的归约结构，其原始数据见 [`DESIGN.md`](DESIGN.md)、[`RESULTS.md`](RESULTS.md) 与 [`experiments/fused_booth/`](../experiments/fused_booth/)。

## 2. 指令输入与输出

| 字段 | 2:4 Sparse VDOT 语义 |
|---|---|
| `vs1[63:0]` | 8 个 INT8 激活值 |
| `vs2[63:0]` | 8 个打包的非零 INT8 权重 |
| `vs2[79:64]` | 四个 4-bit 掩码，按低位到高位排列，每个掩码恰有两个有效位 |
| `vd[31:0]` | 第一个 32-bit 有符号部分和 |
| `vd[63:32]` | 第二个 32-bit 有符号部分和 |
| `vd[127:64]` | 清零 |

稀疏指令约束为 `SEW=e8`、`LMUL=m1`、`VL=8`、`vstart=0` 和合法的四组 2:4 掩码。不满足条件时，执行单元产生非法指令异常。Dense 指令继续按照原有 `vdot.vv` 语义计算 8 个有符号 INT8 元素的点积，写回低 32 位，其余位清零。

**两条指令的编码、操作类型及异常判断以 [`patches/s24/`](../patches/s24/) 中的实际 RTL/NEMU 补丁为准。**

## 3. 数据通路

`VIAluFix` 在乘法器前增加激活值选择逻辑：对于每个 2:4 掩码，按有效位顺序从四个候选激活值中选取两个，与打包的两个非零权重相乘。四组掩码共复用八个 INT8 乘法器，乘积进入 19-bit CSA 归约网络；两个独立的部分和分别符号扩展至 32 位写回。

FastSel 通过直接利用掩码位构造选择逻辑，避免“先编码索引、再动态选择”的组合逻辑链。输出使用与原执行单元对齐的流水线寄存器。Dense 指令与稀疏指令通过操作类型选择相应结果，NEMU 使用独立的顺序参考计算进行差分验证。

## 4. 上游模块修改

| 仓库 | 修改内容 |
|---|---|
| XiangShan | `VecDecoder` 中加入指令译码；`VIAluFix` 中增加稀疏选择、CSA 归约和结果/异常选择 |
| Yunsuan | 定义稀疏 VDOT 的功能单元操作类型 |
| Rocket Chip | 定义稀疏 VDOT 的指令编码 |
| NEMU | 实现独立的指令参考行为与异常条件，供 Difftest 使用 |
| nexus-am | 提供测试与基准程序 |

五份补丁、对应的基础 Git 提交和 SHA256 清单位于 [`patches/s24/`](../patches/s24/)。补丁在记录的基础提交上通过适用性检查。此结果不等同于已在全新机器上完成端到端重建。

## 5. 功能验证

记录的测试包括 Dense 功能回归、稀疏运算验证，以及基于 XiangShan + NEMU Difftest 的完整 INT8 MLP 应用。PairAcc 应用测试记录：

- 32/32 个样本的预测与 Python INT8 参考结果一致；
- 31/32 个样本分类正确；
- 中间点积和隐藏层输出经过参考值检查；
- 仿真器报告 `HIT GOOD TRAP`。

这些是应用和指令正确性的证据；不能把定向测试数量等同于应用样本数量。

## 6. INT8 MLP 性能

测试模型为 64→32→10 的两层 INT8 MLP，使用 2:4 稀疏权重，共 32 个样本。运行包含 3 轮预热、5 轮测量，按相同测试中的统计周期比较。

| 计算方式 | 每 32 个样本的周期数 |
|---|---:|
| Specialized | 19,387 |
| **PairAcc（最终应用）** | **19,308** |

PairAcc 的 Layer 0 使用不同的部分和累加顺序；不需要修改 RTL 或 NEMU。这里测量的是小型完整 MLP 的仿真周期，不是单条 VDOT 延迟或 LLM 的 tokens/s。此前 Dense 微基准的 RVV 周期数不能与本次应用周期数直接构造同条件加速比。

证据见 [`PairAcc 结果`](../results/vdot-s24/real-int8-pairacc/summary.txt) 和 [`应用源码`](../software/VDOT_Real_INT8_PAIRACC/)。

## 7. 综合与时序评估

采用 Nangate45 标准单元库映射生成的完整 `VIAluFix` 面积为 **49,354.172 μm²**。相对于禁用稀疏功能的 **48,587.028 μm²**，面积增量为 **767.144 μm²（+1.579%）**。FastSel 相对优化前减少 **163.324 μm²（−0.330%）** 的映射面积。

STA 在 10 ns 理想时钟约束下，FastSel 的全模块最差 Setup Slack 为 **2.71 ns**，优化前为 **2.99 ns**；因此不宣称全模块最差时序得到改善。综合与 STA 的完整条件、原始证据见 [`S24_PPA.md`](S24_PPA.md)。尚未进行布局布线、真实功耗估计或物理时序签核。

## 8. 复现入口

在同时包含 `xs-env` 与 `cie2026-jade-vdot` 的目录中，将 `xs-env` 及其子仓库检出到 `patches/s24/*-base.txt` 指定的提交并初始化子模块，然后执行：

```bash
bash cie2026-jade-vdot/scripts/apply-s24-patches.sh "$(pwd)/xs-env"
```

完成 XiangShan 仿真器与 NEMU 的必要构建后，运行应用：

```bash
cd xs-env
nix develop -c bash ../cie2026-jade-vdot/software/VDOT_Real_INT8_PAIRACC/run.sh
```

`run.sh` 将已保存的应用源文件复制到 nexus-am 测试目录，编译并启动差分仿真；默认工作区为 `$HOME/work/xiangshan-vdot`，可通过 `VDOT_WORKSPACE` 指定。根目录原有的 `versions.env` 与 `scripts/apply-patches.sh` 只用于 Dense 归约结构的实验复查，并非本参赛方案的默认构建入口。
